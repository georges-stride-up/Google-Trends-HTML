# Google-Trends-HTML

## Overview
A serverless admin tool for publishing Google Trends embed pages to a GitHub repository. Users paste a Google Trends embed script into an admin UI, which parses it, generates a clean HTML page, and publishes it to the repo via a serverless function that calls the GitHub Contents API.

## Architecture
- **Frontend-only static site** — no build step, no package manager, no framework
- **Styling**: [water.css](https://watercss.kocber.com/) CDN (classless CSS)
- **Deployment target**: Vercel (primary) or Netlify (alternative)
- **Repo owner**: `georges-stride-up` / `Google-Trends-HTML`
- **Production endpoint**: `https://google-trends-html.vercel.app/api/publish`

## Key Files
| File | Purpose |
|---|---|
| `admin.html` | Main admin UI — paste embed script, parse, preview, publish |
| `index.html` | Auto-generated library listing all trend pages (also regenerated by GitHub Action) |
| `api/publish.js` | Vercel serverless function — receives POST, writes file + updates index via GitHub API |
| `netlify/functions/publish.js` | Netlify equivalent of the above |
| `iso-map.js` | Helper mapping ISO 3166 alpha-2 country codes to friendly slugs |
| `.github/workflows/update_index.yml` | GitHub Action that regenerates `index.html` on push to `main` when HTML files change |
| `*.html` (root) | Individual trend embed pages (e.g., `bottes-neige.html`, `parfum.html`) |

## Publish Flow
1. User pastes a Google Trends `<script>` embed into `admin.html`
2. Client-side JS parses keyword, geo, time range, language from the script
3. Generates a filename: `{keyword}_{geo}_{timerange}.html`
4. On confirm, POSTs to the serverless function (`/api/publish`)
5. Serverless function uses `GITHUB_TOKEN` env var to create/update the file via GitHub Contents API
6. Function also auto-updates `index.html` to include a link to the new page
7. GitHub Action on push further regenerates `index.html` from all HTML files in root

## Environment Variables
- `GITHUB_TOKEN` — required on the serverless platform (Vercel/Netlify). Must have repo contents write permission.

## Development
- No dependencies to install — open HTML files directly in a browser
- `admin.html` stores the endpoint URL in `localStorage` (key: `trends_endpoint`)
- For local testing, use "direct mode" with a short-lived PAT (not for production)

## Conventions
- Filenames for trend pages use slugified format: lowercase, hyphens for spaces, underscores as separators between keyword/geo/time
- All trend HTML pages are minimal: full-viewport iframe-style embed with no extra chrome
- French language UI in admin and index pages
